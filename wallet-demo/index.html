INFO

How this demo works

A random wallet key is encrypted on this device; an accepted model check triggers its decryption for signing.

  1. 1
    Create a local demo wallet

    The browser generates a random wallet key and encrypts it with AES-GCM. The encrypted key and a non-exportable Web Crypto key are stored in this browser; there is no MetaMask custody.

  2. 2
    Enroll a dataset demo profile

    Choose an anonymous subject ID. The local service builds its template from cached session-4 recordings; the mapping to the wallet stays in this browser.

  3. 3
    Run the EEG model

    The local Python service evaluates a cached session-6 recording, compares the 8-channel embedding with the profile template, and checks the threshold calibrated on session 5.

  4. 4
    Passing match decrypts the key

    On a pass, this page retrieves the browser-held AES key and decrypts the wallet private key into JavaScript memory. The model does not derive the cryptographic key.

  5. 5
    Unlocked wallet signs

    You explicitly approve signing the challenge with the decrypted local wallet, then separately confirm a zero-value self-transfer. The app signs and broadcasts it through the Base Sepolia RPC.

What reaches the blockchain

Only the ordinary zero-value self-transfer is broadcast. The EEG sample, model score, template, and match result are not included. No smart contract checks the EEG. This is local decryption followed by ordinary wallet signing—not an on-chain biometric check.

Important: sessions 4–6 are unseen by training weight updates, but the people are the same 100 dataset subjects represented in training. This demonstrates cross-session matching for known dataset identities—not enrollment or validation of entirely new people.

LIMITS

Why it is demo-only

Useful for showing the interaction; insufficient for protecting a wallet.

  • Public recordings can be replayed. Anyone with the dataset can submit the same sample; this does not demonstrate liveness or headset capture.
  • The browser gate is bypassable. Browser code and IndexedDB are under the user's control; modified code can retrieve the stored AES key and decrypt the vault without passing the model.
  • Dataset identities are not wallet owners. The 100 subject IDs are anonymous research labels, not enrollment of real wallet users.
  • Not validated across hardware or real users. Results are from one dataset and do not establish passive recognition, different headset placements, or spoof resistance.
  • No ZK authorization proof is generated. The demo reports a model score locally; it does not prove inference or matching on-chain.
  • This does not equal secure biometric key storage. The private key exists in browser memory while unlocked, and JavaScript cannot guarantee secure erasure.

Use only a throwaway Base Sepolia account and test ETH. Never use real funds or connect a mainnet wallet.
